# ReadySuite 官网架构

[English](ARCHITECTURE.md)

## 信息架构

- `/`：只表达品牌主张，并提供一个交互式产品舞台。
- 产品路由：每个产品使用独立页面和独立 SEO 元数据。
- `/downloads`、`/support`、`/privacy`：基于同一产品目录生成的公共运营页面。
- `/en/...`：每个公开页面可独立渲染和抓取的英文版本。
- `/guides/...` 与 `/en/guides/...`：围绕搜索任务编写、并由相关产品页链接的实用指南。

首页负责吸引与分流，产品页负责说明、演示与转化，公共页负责发布、支持和隐私边界。不同页面不重复堆砌同一套产品介绍。

## 产品更新边界

1. `app/product-registry.ts`：产品顺序、路由、仓库和按钮目标的唯一入口。
2. `app/product-ui.tsx`：中英文产品文案，以及按产品标识分发的视觉模块。
3. `app/<product>/page.tsx`：搜索和社交分享使用的静态元数据。
4. `public/`：隐私安全的截图、封面和动效素材。
5. `app/seo.tsx`：多语言元数据、规范链接、`hreflang` 对应关系和 schema.org 结构化数据。
6. `app/guide-content.ts`：与产品定位文案分离维护的中英文指南内容。

新增产品只需要补充一项目录配置、一份双语文案、一个视觉模块、一个元数据页面和 sitemap 入口，不再增加新的首页长段落。

中文继续以 `/` 为默认入口，英文固定使用 `/en`。语言切换必须在稳定 URL 之间导航，不能只切换客户端状态。新增公开路由时，必须同步提供对应语言页面、双向语言标记、sitemap 入口和至少一条站内链接。

## 产品状态规则

- 版本号来自公开 GitHub Release、Tag，或明确标注的源码预览。
- 没有公开 Release 的产品只能链接仓库，不得描述为可下载版本。
- 优先使用真实产品素材；公开素材不得包含账号、Token、本地路径、私人内容或用户数据。
- GitHub 链接在新标签页打开，站内产品导航保留在当前标签页。

## 验证要求

每次用户可见更新都必须完成：

- 生产构建；
- 桌面端和移动端浏览器检查；
- 中文和英文检查；
- 横向溢出与控制台错误检查；
- 版本号和双语更新日志同步；
- 提交前敏感信息扫描。
- 检查渲染后的标题、规范链接、`hreflang`、JSON-LD、robots 和 sitemap。
